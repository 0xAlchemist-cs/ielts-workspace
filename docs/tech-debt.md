# 技术债清单（三轮审计收尾时登记）

状态基准：`7f0faf5`（三轮审计全部关闭，CI 绿）。
本清单是**有意留到独立任务**的事项——不是未完成的缺陷修复，而是范围决策。

## 1. DNS rebinding 的连接级 IP 钉扎（安全加固）

- 现状：`fetchPublicPage` 每跳 fetch 前即时做 DNS 解析校验（`checkPublicHttpUrl`），
  解析与连接之间的窗口为毫秒级，但理论上存在 TOCTOU（解析后重绑定）。
- 完整方案：引入 `undici` 依赖，用自定义 `Agent`（connect lookup 钩子）把校验
  钉到**连接时刻**。涉及新增网络依赖，故未在审计修复轮引入。
- 触发条件：应用需要暴露到不可信网络时优先级提升（当前绑定 127.0.0.1，风险面有限）。

## 2. submitRetentionReview 的事务化（数据一致性）

- 现状：评分函数内部跨多表写入（retrievalItems、chunks、reviewHistory 等），
  中途失败会留下**部分**学习状态写入。错题训练的占位已能释放（round-3），
  但已写入的部分状态不会回滚。
- 完整方案：把整个评分路径收进一个数据库事务（better-sqlite3 同步事务），
  或引入"阶段状态机 + 安全重试"语义，保证重试不重复计算部分评分。
- 影响面：`/api/review/answer`、错题训练、mission 批次共用此函数——需要专门
  的失败注入测试矩阵后再动。

## 3. Windows 下 pre-push 钩子的 SIGPIPE（开发体验）

- 现状：本地门禁（`.githooks/pre-push` → verify:all，约 5–6 分钟）在
  Git-for-Windows 上长运行后，git 与 SSH 子进程管道断裂（exit 141），
  钩子已通过但传输被杀，需 `--no-verify` 重推。
- 远端 CI 已强制同一门禁，本地钩子结果仅供参考；根因疑在 Windows 进程
  管道超时行为，修复价值低、成本高。

## 4. 自适应权重的完整决策闭环（产品取舍）

- 现状：六维权重归一后驱动"紧迫度→训练时长"（recommendLength），主技能
  仍由最弱项 + 轮换规则决定。
- 若产品上需要"权重直接决定主技能"，属于 mission 结构重设计
  （现有 plan 无写作槽位），应单独立项而非补丁。

## 5. 安全探针的网络不确定性（测试策略，已接受）

- verify-security 对网络类探针失败标记 indeterminate（不阻断 CI、不计为
  通过，结尾显式汇总）。确定性断言（表单校验类）仍严格 exit 1。
- 若未来有稳定可达的探针靶站，可把 redirect 探针转为确定性。

## 复核节奏约定

三轮审计循环已收尾（13 + 7 + 2 项全部关闭）。下一阶段为**稳定性验证**：

学习闭环；数据库每日经 `scripts/backup-workspace.py` 异地备份。
